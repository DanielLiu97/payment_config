## 一、工具是什么

一句话：**把运营填好的支付配置 Excel，逐行跟星宿平台线上接口做比对，发现不一致就报错。**

校验范围包括：商品ID、价格ID、总价（USD）、月均价、周期、买赠周期、商品名称等。支持 PC/Android/iOS/Mac/Mobile/Web 多平台，支持正式和测试环境。

运营日常使用的是 **Web 自助页面**（`http://<机器IP>:8010/`），不需要接触代码。

## 二、运营使用流程（Web 页面）

| 步骤 | 操作 | 注意 |
|------|------|------|
| 1 | 打开页面，点击「下载 xlsx 模板」 | 不要改表头 |
| 2 | 在模板中填好配置数据 | 格式见下方「Excel 填写规范」 |
| 3 | 上传文件，填写平台/环境/国家/Sheet 编号，点击启动 | 国家只影响橱窗场景，价格统一按 USD 校验 |
| 4 | 等待进度条跑完，看结果 | 通过 = 无异常；不通过 = 至少 1 条错误 |

**Sheet 编号格式**：`1,3,5-8`（逗号分隔，支持范围）  
**指定行号**（高级，可不填）：`30,32,44`  
**Bot 消息**：默认勾选，结果会推到群里

## 三、Excel 填写规范（快速参考）

| 列 | 字段 | 必填 | 说明 |
|----|------|------|------|
| A | 国家 | 是 | 国家代码如 US、MY、IN |
| B | 会员类型 | 是 | Pro、Premium 等 |
| C | 价格类型 | 是 | 原价、折扣价、试用、挽回 等 |
| D | 商品序号 | 是 | 从 1 开始的正整数 |
| E | 周期 | 是 | 格式：1年、3个月、6个月 |
| F | 总价 | 是 | USD 金额 |
| G | 均价 | 是 | USD/月 |
| H | 价格ID | 可空 | 填了就校验，不填跳过 |
| I | 商品ID | 可空 | **空则整行跳过不校验** |
| J | 买赠周期 | 条件 | 原价可不填，其他建议填 |
| K | 橱窗ID | 是 | 见下方格式说明 |
| L/M | 体验价 | 可选 | 体验价价格/周期，有则校验 |

**K 列格式**：
- `支付页：3553` 或 `支付：3553` — 指定橱窗
- 留空 — 沿用上一行橱窗
- `/` — 不走橱窗，按商品ID直接查后台
- `7664+7722` — 双橱窗都校验

**合并单元格**：A/B/C 列相同内容必须合并，程序会自动向下填充。

## 四、常见问题 & 处理方式

### 4.1 运营侧问题

| 问题 | 原因 | 处理 |
|------|------|------|
| 「模板表头不匹配」 | 用了旧模板或手动改了表头 | 重新从页面下载模板，只粘贴数据 |
| 「cookie已过期，请联系管理员更新后，再发起任务」 | 服务端 `PAYMENT_ADMIN_COOKIE` 失效 | 联系维护人按「Cookie 更新」章节刷新 `ovsmgr_sid` 并重启 Web 服务 |
| 任务秒完成，提示「未检测到可校验数据」 | I 列（商品ID）全为空 | 检查数据，确保 I 列有值 |
| 校验结果不通过但运营认为数据是对的 | 价格容差 ±0.5 USD，超过就报错 | 确认 Excel 中 USD 价格是否准确；若确定无误，记录争议让维护人回来确认规则 |
| 月均价校验不过 | 计算公式：`总价 ÷ (主周期月数 + 买赠月数)` | 确认 J 列买赠周期是否填对 |
| 页面打不开 | 服务可能挂了 | 见下方「服务维护」章节 |
| Bot 没收到消息 | 勾选项关闭 / webhook 网络波动 | 以页面结果为准，Bot 只是辅助通知 |
| 「online 环境污染」拦截 | 本机 hosts 文件被改（SwitchHosts） | 需要维护人检查 DNS 映射，运营无法自行解决 |
| 「队列已满」 | 排队任务超过 4 个 | 等前面任务跑完再提交 |

### 4.2 技术侧问题

| 问题 | 说明 |
|------|------|
| Cookie 过期了怎么办 | 见下方「Cookie 更新」章节 |
| 服务怎么重启 | 见下方「服务维护」章节 |
| 任务数据保留多久 | 永久保存，不会自动清理 |
| 并发上限 | 同时执行 2 个任务（`WEB_WORKERS=2`），队列最多再排 4 个 |

## 五、服务维护

### 5.1 确认服务状态

浏览器访问 `http://<机器IP>:8010/`，能打开就是正常的。

### 5.2 重启服务

**重启前先确认没有进行中的任务**：

```powershell
rg '"status"\s*:\s*"(running|queued)"' .\web_data\tasks\**\meta.json
```

- 有输出 → 等任务跑完再重启
- 无输出 → 可以安全重启

**停止服务**：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\windows\stop_web_service.ps1
```

**启动服务**：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\windows\start_web_service.ps1
```

工作目录：项目根目录 `payment_config_checker\`

### 5.3 Cookie 更新

Cookie 是访问星宿后台 API 的凭证，过期后所有任务都会失败。

**判断是否过期**：任务报错日志中出现 401/403，或大量行报「接口返回为空」。

**更新步骤**：

1. 浏览器打开 `https://example.com/` 并登录
2. F12 → Network → 随意点个请求 → 复制 Cookie 中 `ovsmgr_sid=xxx` 的值
3. 编辑 `scripts\windows\web_service.env.ps1`，更新 `PAYMENT_ADMIN_COOKIE` 的值
4. 重启服务（见上文）

### 5.4 服务日志位置

| 日志 | 路径 | 用途 |
|------|------|------|
| 服务启动日志 | `web_data/service/web.stdout.log` | 看服务是否正常启动 |
| 错误日志 | `web_data/service/web.stderr.log` | 看启动报错 |
| 全局运行日志 | `logs/payment_config_checker.log` | 详细执行记录 |
| 单任务日志 | `web_data/tasks/task-YYYYMMDD-NN/task.log` | 某个任务的完整日志 |

## 七、环境与网络

| 环境 | 橱窗服务器 | 说明 |
|------|-----------|------|
| online（正式） | `example.com` | 日常使用 |
| test（测试） | `example.com` | 预发布验证 |

**后台管理 API**：`https://example.com/shopwindow/shop-admin/manage/1`（或旧域名 `example.com`）

**在线环境保护**：服务启动时会检测 DNS 是否被 SwitchHosts 污染。如果检测到在线地址解析到内网 IP，会拦截任务创建。这是为了防止用测试数据做了线上校验却不自知。

## 八、如果遇到搞不定的问题

1. **不影响运营正常使用的**：记下问题，等维护人回来处理。
2. **服务彻底不可用的**：尝试重启（按上文步骤）。重启后还不行，检查 Cookie 是否过期。
3. **涉及校验规则争议的**：让运营先记录，不要改代码或配置，等维护人确认口径。
4. **机器本身的问题**（断电、断网等）：联系 IT 处理硬件/网络，服务设了开机自启，机器恢复后会自动拉起。
